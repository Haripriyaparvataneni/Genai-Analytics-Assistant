# GenAI Analytics Assistant (Text-to-SQL)

A natural-language analytics assistant over a SQLite sales/inventory
database. Ask a question in plain English, get the generated SQL plus the
query result.

> **Portfolio demo.** The database is fully synthetic — generated by
> `data/build_db.py`. Nothing here comes from an employer or any proprietary
> system.

## How it works

- `data/build_db.py` creates `data/sales.db` with three tables: `products`,
  `sales` (120 seeded days of transactions), and `inventory` (2 warehouses).
- `text_to_sql.py` defines a pluggable LLM interface:
  - **Default: `HeuristicLLM`** — a local, pattern-based question parser
    that runs fully offline. No API keys, no network, no AWS.
  - **Optional: `BedrockLLM`** — an Amazon Bedrock (Claude) backend for
    free-form questions. Clearly marked OPTIONAL: enabled only with
    `USE_BEDROCK=1` and requires you to `pip install boto3` plus AWS
    credentials. The default path never imports boto3.
- `schema.py` exposes the DB schema text used in prompts.
- `app.py` is the CLI: prints the generated SQL, executes it on SQLite,
  prints the results. Supports `--interactive` mode.

## Run it (no AWS needed)

```bash
python data/build_db.py
python app.py "What is the total revenue?"
python app.py --interactive
```

## Sample session (real output)

```
$ python app.py "Which products have low stock?"
Question: Which products have low stock?
SQL: SELECT p.name, i.warehouse, i.stock_qty, i.reorder_level FROM inventory i
     JOIN products p ON i.product_id = p.product_id
     WHERE i.stock_qty < i.reorder_level ORDER BY i.stock_qty;
name | warehouse | stock_qty | reorder_level
Vertex Standing Desk | WH-North | 0 | 30
Drift Yoga Mat | WH-South | 12 | 30
Pulse Bluetooth Speaker | WH-North | 29 | 30
```

See `examples.md` for 8 verified question → SQL → result examples.

## Optional Bedrock backend

```bash
pip install boto3        # optional; NOT in requirements.txt
USE_BEDROCK=1 python app.py "Compare Q1 vs Q2 revenue by category"
```

Honest scope note: the default local model handles common analytics
question shapes reliably (see `examples.md`); it raises a clear error for
questions outside its patterns rather than hallucinating SQL. That's an
intentional trade-off for a demo that runs anywhere with zero setup.

## Layout

```
data/build_db.py      # synthetic SQLite DB generator (seeded)
schema.py             # DB schema text for prompts
text_to_sql.py        # pluggable LLM interface: local heuristic (default) + optional Bedrock
app.py                # CLI: question -> SQL -> results
examples.md           # 8 verified example questions with SQL + results
requirements.txt      # stdlib only for the default run (boto3 intentionally optional)
```
